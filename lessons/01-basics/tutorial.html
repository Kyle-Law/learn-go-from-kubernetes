    Go basics: modelling a Pod

    You already know what a Pod looks like in YAML. In this tutorial you'll learn the Go you need to describe one in code: structs, slices, maps, methods, and the testing workflow you'll use for every lesson.

    • About 30 minutes
    • 11 self-checks
    • Then: pod.go exercises

    Your first Go file

    Every Go file starts with a package line. Here is a complete program:

    
package main

import "fmt"

func main() {
	fmt.Println("hello from a pod")
}
    • package main plus func main() makes a program you can run. Any other package name (like basics in this lesson) is a library that other code or tests use.
    • import "fmt" pulls in the standard library's formatting package. Unused imports are a compile error, not a warning.
    • Braces are required, and the opening { must sit on the same line. Run gofmt (most editors do it on save) and never think about formatting again.

    Packages are folders

    All .go files in one folder belong to the same package and can see each other's code. That's why pod_test.go can call functions from pod.go with no import.

    
go run .                         # build and run package main in this folder
go test ./lessons/01-basics/     # run one package's tests
go test ./...                    # run every package under here
go vet ./...                     # catch common mistakes the compiler allows
    Trap

    Always start folder paths with ./. go test lessons/01-basics fails with "is not in std" because, without ./, Go reads the path as an import path like encoding/json and looks in the standard library.

    From Kubernetes

    The module name in go.mod (github.com/Kyle-Law/learn-go-from-kubernetes) works like an API group: it's the prefix that makes every package path globally unique. k8s.io/api/core/v1 is "module k8s.io/api, folder core/v1".

    You add import "strings" to a file but never use it. What happens on go build?

    Go treats unused imports and unused local variables as errors to keep code clean. Editors with gopls add and remove imports for you automatically.

    Variables, types, and zero values

    
var replicas int32 = 3   // explicit type
var image = "nginx:1.27" // type inferred: string
ready := true            // short form, only inside functions

var restarts int         // no value given: restarts == 0

    := declares and assigns. Use it inside functions for almost everything. = assigns to a variable that already exists.

    Zero values

    Every variable starts at its type's zero value. There's no "undefined" and no uninitialized memory.

    TypeZero value
    int, int32, float640
    string"" (never nil)
    boolfalse
    pointers, slices, maps, interfaces, channels, functionsnil
    structsevery field at its own zero value
    From Kubernetes

    Zero values are like fields you leave out of a manifest. A Pod with no restartPolicy still has one; it's just the default. Go code is written so the zero value is useful whenever possible.

    What does this print?

    
var namespace string
fmt.Println(namespace == "", namespace == nil)

    A string can never be nil, so comparing it to nil is a compile error. Its zero value is "". Only pointers, slices, maps, interfaces, channels and functions can be nil.

    Structs: your resource schemas

    A struct groups named fields, exactly like a section of a manifest.

    
type ContainerPort struct {
	Name          string
	ContainerPort int32
	Protocol      string
}

// Create one with a composite literal. Name the fields.
p := ContainerPort{Name: "http", ContainerPort: 8080}

fmt.Println(p.ContainerPort) // 8080
fmt.Println(p.Protocol)      // "" (omitted, so zero value)
p.Protocol = "TCP"
fmt.Printf("%+v\n", p)       // {Name:http ContainerPort:8080 Protocol:TCP}

    Structs can contain other structs and slices of structs, so you can nest them as deeply as a real PodSpec.

    Exported vs unexported

    Go has no public or private keywords. The first letter decides:

    • Name, ContainerPort, NewStore: capitalized, so exported. Other packages can use them.
    • name, readyCount, key: lowercase, so unexported. Only code in the same package can use them.

    This applies to types, functions, methods, struct fields, constants and variables.

    From Kubernetes

    Open k8s.io/api/core/v1/types.go and you'll find type Pod struct, type PodSpec struct, type Container struct: the Go version of every schema you've written YAML for. Every field is exported so that other packages, like client-go, can read it.

    Which field values does c end up with?

    
type Probe struct {
	Path    string
	Port    int32
	Timeout int32
}
c := Probe{Path: "/healthz"}

    Fields you leave out of a literal get their zero value. An int32 can't be nil; its zero value is 0.

    Named types and constants: Go's enums

    Go has no enum keyword. Instead you declare a new type based on string (or int) and a set of constants of that type:

    
type RestartPolicy string

const (
	RestartAlways    RestartPolicy = "Always"
	RestartOnFailure RestartPolicy = "OnFailure"
	RestartNever     RestartPolicy = "Never"
)

var policy RestartPolicy = RestartAlways
if policy == RestartNever {
	// ...
}

    The named type documents intent and lets the compiler stop you mixing up unrelated strings: a plain string variable can't be assigned to a RestartPolicy without an explicit conversion, RestartPolicy(s).

    From Kubernetes

    This is exactly how corev1.PodPhase, corev1.RestartPolicy and corev1.ServiceType are defined. The Phase type in pod.go copies that pattern.

    Slices: lists like spec.containers

    A slice is a growable, ordered list. Its type is written []T.

    
envs := []string{"LOG_LEVEL", "PORT"}
fmt.Println(len(envs))     // 2
fmt.Println(envs[0])       // "LOG_LEVEL"

envs = append(envs, "DEBUG") // append returns the new slice: always reassign it

    Looping with range

    
for i, name := range envs {
	fmt.Println(i, name)    // index and value
}
for _, name := range envs { // _ throws away the index
	fmt.Println(name)
}
for i := range envs {       // index only
	fmt.Println(i)
}
    Trap

    The value variable in range is a copy of the element. Changing it doesn't change the slice:

    
for _, p := range ports {
	p.Protocol = "TCP"         // changes the copy only
}
for i := range ports {
	ports[i].Protocol = "TCP"  // changes the real element
}

    nil slices are fine

    A slice declared with var is nil, and that's normal: len is 0, range runs zero times, and append allocates storage when it needs to.

    
var names []string          // nil
names = append(names, "web") // works: ["web"]

    What happens with this line?

    
append(envs, "DEBUG")

    append may need to allocate a new, bigger array, so it returns the slice instead of changing it in place. Go refuses to compile a call that throws that result away. Write envs = append(envs, "DEBUG").

    pods holds two pods, both in phase "Pending". What's the phase of pods[0] afterwards?

    
for _, p := range pods {
	p.Phase = "Running"
}

    p is a copy of each element, so the slice is unchanged. To modify elements, loop with the index: for i := range pods { pods[i].Phase = "Running" }.

    Maps: labels and annotations

    A map stores key/value pairs. Its type is map[K]V, and metadata.labels is a map[string]string.

    
annotations := map[string]string{
	"team":  "payments",
	"owner": "alice",
}
annotations["oncall"] = "bob"   // add or overwrite
delete(annotations, "owner")    // remove (no-op if missing)
fmt.Println(len(annotations))   // 2

    Reading: the "comma ok" idiom

    Reading a missing key doesn't fail. It returns the value type's zero value. To tell "missing" from "present but empty", ask for a second result:

    
owner := annotations["owner"]       // "" whether missing OR set to ""
owner, ok := annotations["owner"]   // ok is false only if the key is missing

if team, ok := annotations["team"]; ok {
	fmt.Println("owned by", team)   // team and ok exist only inside this if
}

    Making maps

    
var a map[string]int          // nil map: reads work, writes PANIC
b := map[string]int{}         // empty, ready to use
c := make(map[string]int)     // same as b
c["restarts"]++               // missing key reads as 0, so this sets it to 1
    Trap

    Writing to a nil map panics with "assignment to entry in nil map". A struct's map field starts as nil, so check and make it before writing. A nil slice is fine to append to; a nil map is not fine to write to.

    Trap

    Map iteration order is random, on purpose, and changes between runs. If order matters, copy the keys to a slice and sort it.

    From Kubernetes

    A label selector like -l app=web,tier=frontend is just a map[string]string too. A pod matches when every key in the selector exists in the pod's labels with the same value. You'll implement that check in the exercises, and the comma-ok idiom is the key to getting the edge cases right.

    What happens?

    
type Node struct {
	Name   string
	Taints map[string]string
}
var n Node
n.Taints["dedicated"] = "gpu"

    n.Taints is a nil map, and the compiler can't catch writes to it. Initialize it first with n.Taints = make(map[string]string).

    labels is {"app": "web"}. What are v and ok?

    
v, ok := labels["tier"]

    Missing keys read as the zero value, "" for strings, with ok == false. That's how you tell "not set" apart from "set to an empty string".

    Control flow

    if

    No parentheses, braces always required. An if can start with a short statement whose variables live only inside the if/else:

    
if restarts > 5 {
	fmt.Println("crash looping")
} else if restarts > 0 {
	fmt.Println("flaky")
}

    for is the only loop

    
for i := 0; i < 3; i++ { }   // classic
for attempts < 5 { }         // like "while"
for { }                       // forever (use break or return to leave)
for _, c := range containers { // over a slice, map, string or channel
	if c.Image == "" {
		continue // skip to the next iteration
	}
}

    Guard clauses: return early

    Idiomatic Go handles the "no" cases first and returns, keeping the happy path unindented:

    
func canSchedule(n Node) bool {
	if n.Unschedulable {
		return false
	}
	if len(n.Taints) > 0 {
		return false
	}
	return true
}

    switch

    
switch policy {
case RestartAlways:
	fmt.Println("always restart")
case RestartOnFailure, RestartNever: // several values in one case
	fmt.Println("maybe not")
default:
	fmt.Println("unknown")
}

    Cases don't fall through, so there's no break to forget.

    You want to keep only the nodes in zone "a". Which loop body does that?

    continue means "skip this one", so its condition must describe what you want to reject. break would stop the whole loop.

    Functions

    
// Types come AFTER names. The return type comes last.
func scale(current, delta int32) int32 {  // current and delta are both int32
	return current + delta
}

// Functions can return several values.
func splitImage(image string) (string, string) {
	name, tag, found := strings.Cut(image, ":")
	if !found {
		return name, "latest"
	}
	return name, tag
}

name, tag := splitImage("nginx:1.27") // "nginx", "1.27"
_, tag = splitImage("busybox")        // ignore the first result

    Multiple return values are how Go reports errors (value, err) and lookups (value, ok). You'll use them constantly from lesson 2 on.

    Arguments are passed by value: a function gets its own copy of a struct. Slices and maps are small headers that point to shared data, so a function can change their elements.

    Methods and receivers

    A method is a function attached to a type. The receiver goes in parentheses before the name:

    
type Node struct {
	Name          string
	Unschedulable bool
	Labels        map[string]string
}

// Value receiver: n is a copy. Good for reading.
func (n Node) Schedulable() bool {
	return !n.Unschedulable
}

// Pointer receiver: n points at the caller's Node. Needed to modify it.
func (n *Node) Cordon() {
	n.Unschedulable = true
}

node := Node{Name: "worker-1"}
node.Cordon()                   // Go passes &node for you automatically
fmt.Println(node.Schedulable()) // false
    Use a pointer receiver (n *Node) when…A value receiver (n Node) is fine when…
    the method changes the structthe method only reads
    the struct is large (avoids copying)the struct is small
    other methods on the type already use pointers (be consistent)
    Trap

    With a value receiver, assigning a new map to n.Labels only changes the copy. Writing into an existing map does reach the caller, because the copy points at the same map. So a value-receiver bug can hide until the map happens to be nil. If a method modifies anything, use a pointer receiver.

    From Kubernetes

    Generated methods such as pod.DeepCopy() and pod.GetName() all have pointer receivers, which is why client-go always works with *corev1.Pod rather than corev1.Pod.

    After n.Cordon(), what is n.Unschedulable?

    
func (n Node) Cordon() {   // note: value receiver
	n.Unschedulable = true
}

n := Node{Name: "worker-1"}
n.Cordon()

    Cordon received a copy of n and changed the copy. Change the receiver to (n *Node) and it works.

    Formatting strings with fmt

    
s := fmt.Sprintf("%s/%s", "default", "web") // returns a string: "default/web"
fmt.Printf("%d restarts\n", 3)              // prints; add \n yourself
fmt.Println("a", 1, true)                   // prints with spaces and a newline

    Sprintf can't check its arguments at compile time. A wrong count or type prints markers like %!d(MISSING) instead of failing. go vet catches these, so run it often.

    What does fmt.Sprintf("%d/%d", 2) return?

    Missing arguments become an error marker in the output, not a compile error. go vet would warn you about this line.

    Tests: how you'll know you're done

    Test files end in _test.go. Each test is a function named TestXxx that takes a *testing.T. Most Go tests, including the ones in Kubernetes, are table-driven:

    
func TestSplitImage(t *testing.T) {
	tests := []struct {      // a slice of anonymous structs: the "table"
		name     string
		image    string
		wantName string
		wantTag  string
	}{
		{"with tag", "nginx:1.27", "nginx", "1.27"},
		{"no tag", "busybox", "busybox", "latest"},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) { // each row becomes a named subtest
			name, tag := splitImage(tt.image)
			if name != tt.wantName || tag != tt.wantTag {
				t.Errorf("splitImage(%q) = %q, %q; want %q, %q",
					tt.image, name, tag, tt.wantName, tt.wantTag)
			}
		})
	}
}
    • t.Errorf records a failure and keeps going. t.Fatalf stops this test immediately.
    • Adding a case means adding one line to the table.
    • Read the table before you code: the rows are the specification, including the edge cases.
    
go test ./lessons/01-basics/                       # all tests in the lesson
go test -v -run TestSelectorMatches ./lessons/01-basics/   # one test, verbose
go test -run 'TestSelectorMatches/missing_key' ./lessons/01-basics/   # one row

    Subtest names have spaces replaced with underscores, as in TestSelectorMatches/missing_key.

    A table has 5 rows and rows 2 and 4 fail with t.Errorf. How many failures do you see?

    t.Errorf marks the test failed but continues, and each t.Run subtest is independent. You'd only stop early with t.Fatalf, and even then only that subtest stops.
