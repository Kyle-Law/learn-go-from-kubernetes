    Encoding: from YAML manifest to Go struct

    Every manifest you kubectl apply becomes a Go struct inside the API server, and every kubectl get -o yaml turns one back into text. This tutorial shows how that conversion works and the traps that come with it.

    • About 35 minutes
    • 9 self-checks
    • Then: types.go, manifest.go

    In Kubernetes, YAML is really JSON

    The API server speaks JSON (and protobuf). YAML is a convenience for humans. The library Kubernetes uses, sigs.k8s.io/yaml, works in two steps:

    
deployment.yaml ──(1) YAML → JSON──▶ {"apiVersion":"apps/v1",...} ──(2) encoding/json──▶ Deployment struct

    So everything that controls decoding is encoding/json behaviour, configured with json struct tags. You never write yaml tags on Kubernetes types.

    
import "sigs.k8s.io/yaml"

var d Deployment
err := yaml.Unmarshal(data, &d)   // data is YAML or JSON
out, err := yaml.Marshal(&d)       // struct → YAML

    A nice side effect: JSON is valid YAML, so the same function parses kubectl get -o json output.

    A field has the tag `json:"containerPort"` and no yaml tag. You parse YAML with sigs.k8s.io/yaml. Which YAML key fills it?

    The YAML is converted to JSON first, then encoding/json decodes it using the json tags.

    Struct tags

    A tag is a string literal written after a field's type, in backticks. The compiler ignores it; libraries read it at runtime (through reflection) to decide how to handle the field.

    
type Service struct {
	Name     string            `json:"name"`
	Type     string            `json:"type,omitempty"`
	Selector map[string]string `json:"selector,omitempty"`
	Port     int32             `json:"port"`
	cache    string            // unexported: never encoded or decoded
	Debug    bool              `json:"-"` // exported, but always skipped
}
    TagEffect
    (no tag)key is the Go field name, e.g. "Port"
    json:"port"key is "port"
    json:"type,omitempty"key "type"; left out when the value is the zero value
    json:"-"never encoded or decoded
    json:",inline" on an embedded structKubernetes convention. To encoding/json this just means "no name", and embedded structs without a name are flattened anyway

    Tag syntax is strict: key:"value", no spaces around the colon, double quotes inside backticks. go vet catches malformed tags.

    Embedded structs are flattened

    
type TypeMeta struct {
	APIVersion string `json:"apiVersion"`
	Kind       string `json:"kind"`
}
type ConfigMap struct {
	TypeMeta                   // embedded, no tag: fields appear at the top level
	Data map[string]string `json:"data,omitempty"`
}
// {"apiVersion":"v1","kind":"ConfigMap","data":{...}}
    From Kubernetes

    Every field in k8s.io/api has a json tag (plus a protobuf tag). The camelCase names you type in YAML (containerPort, matchLabels, imagePullPolicy) come straight from those tags.

    What does json.Marshal output for this?

    
type probe struct {
	path string `json:"path"`
	Port int32  `json:"port"`
}
json.Marshal(probe{path: "/healthz", Port: 8080})

    Only exported (capitalized) fields are encoded. A lowercase field is skipped silently, even with a tag. go vet warns about tags on unexported fields.

    Marshal and Unmarshal

    
import "encoding/json"

svc := Service{Name: "web", Port: 80}

data, err := json.Marshal(svc)            // struct → []byte
// {"name":"web","port":80}

pretty, err := json.MarshalIndent(svc, "", "  ") // with newlines and indentation

var back Service
err = json.Unmarshal(data, &back)           // []byte → struct: pass a POINTER
    • Encoders work with []byte. Convert with string(data) to print and []byte(s) to go the other way.
    • Unmarshal needs a pointer so it can fill in your variable.
    • Map keys are sorted in the output, so encoding is deterministic.
    • Fields are written in struct declaration order.

    Two decoding traps

    Trap 1: keys match case-insensitively

    Unmarshal prefers an exact match but accepts "PORT", "Port" or "port" for a field tagged port, and accepts "apiversion" for an untagged APIVersion field. So decoding can look correct even when your tags are wrong. Encoding shows the truth: test your tags by marshalling.

    Trap 2: unknown keys are silently ignored

    A typo like replcas: 3 doesn't fail; the field just keeps its zero value. json.NewDecoder(r).DisallowUnknownFields() turns this into an error. It's also why kubectl apply added server-side field validation: it warns about unknown fields instead of dropping them.

    The field is Port int32 with no tag. What does json.Unmarshal([]byte(`{"port": 80}`), &svc) set svc.Port to?

    Decoding matches keys case-insensitively, so it works without a tag. But json.Marshal would write "Port", which the Kubernetes API wouldn't recognize. Always tag.

    What's wrong with json.Unmarshal(data, svc), where svc is a Service value?

    Go passes arguments by value, so Unmarshal would only get a copy. It detects this and returns an InvalidUnmarshalError. Pass &svc. (It compiles because the parameter is any.)

    omitempty in detail

    omitempty leaves a field out when it holds its zero value:

    Field typeOmitted when
    string""
    numbers0
    boolfalse
    slice, mapnil or empty (length 0)
    pointer, interfacenil
    structnever
    Trap

    omitempty has no effect on a struct field: an empty struct still prints as {}. If a nested struct must disappear when unset, make the field a pointer (*Status), which omitempty omits when nil. (Go 1.24 adds an omitzero option for this, but this course uses Go 1.23.)

    From Kubernetes

    This is why kubectl get -o yaml sometimes shows status: {} or creationTimestamp: null: those fields are non-pointer structs, so they're always written.

    The field is Replicas int32 `json:"replicas,omitempty"` and you scale to zero (Replicas = 0). What happens when you send the JSON to the API server?

    0 is the zero value, so omitempty drops it. A plain int32 can't tell "zero" apart from "not set". The next section fixes this.

    Pointers for optional fields

    A pointer holds the address of a value. *int32 is "pointer to an int32". It gives a field three states instead of two:

    Go valueJSON with omitemptyMeaning
    nil(field omitted)not set; use the default
    pointer to 0"replicas":0explicitly zero
    pointer to 3"replicas":3explicitly three

    Pointer basics

    
port := int32(8080)
p := &port         // & takes the address: p is a *int32
fmt.Println(*p)    // * dereferences: 8080
*p = 9090          // writes through the pointer: port is now 9090

var timeout *int32 // nil
if timeout != nil { // ALWAYS check before dereferencing
	fmt.Println(*timeout)
}
// *timeout here would panic: nil pointer dereference

    You can't take the address of a literal or constant: &3 and &"web" don't compile. You need a variable first. (Struct literals are the exception: &Pod{} is allowed.)

    It's safe to return a pointer to a function's local variable or parameter. Go notices and keeps the value alive for as long as it's referenced.

    
func newProbe(path string) *Probe {
	p := Probe{Path: path, Port: 8080}
	return &p   // fine in Go (unlike C)
}
    From Kubernetes

    That's why so many API fields are pointers: a Deployment's Replicas *int32, a Job's Suspend *bool, a Pod's TerminationGracePeriodSeconds *int64. A pointer is used wherever "unset" needs to be different from the zero value, so the server can apply a default.

    spec.Replicas is a *int32 and the manifest didn't set it. What does n := *spec.Replicas do?

    An unset pointer field is nil, and dereferencing nil panics. Check if spec.Replicas != nil first and choose the default yourself.

    A first look at generics

    Setting a pointer field from a literal is clumsy: you need a temporary variable every time. A helper would be nice, but without generics you'd need one for each type: Int32Ptr, BoolPtr, StringPtr… Kubernetes really did have all of those.

    Type parameters let one function work for many types:

    
// [T any] declares a type parameter T that can be any type.
func First[T any](items []T) (T, bool) {
	var zero T          // zero value of whatever T is
	if len(items) == 0 {
		return zero, false
	}
	return items[0], true
}

name, ok := First([]string{"web", "api"}) // T inferred as string
port, ok := First([]int32{80, 443})       // T inferred as int32

    Go usually infers T from the arguments, so you rarely write First[string](...). The part in brackets after T is a constraint: any allows every type, and cmp.Ordered allows only types that support <:

    
func Max[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}
    From Kubernetes

    k8s.io/utils/ptr replaced the old Int32Ptr-style helpers with a single generic ptr.To(v). You'll write your own in the exercise.

    What's the type of x?

    
x, _ := First([]bool{true, false})

    Go infers T = bool from the []bool argument, so the result type T is bool. Unlike any, generics keep the real type, with no type assertion needed.

    Editing nested slices in place

    You met the range-copy trap in lesson 1. It matters more with deeply nested types, because the path to the element gets long. Two clean ways to edit an element:

    
ports := svc.Spec.Ports

// 1. Index into the slice
for i := range ports {
	if ports[i].Name == "http" {
		ports[i].Port = 8080
	}
}

// 2. Take a pointer to the element
for i := range ports {
	p := &ports[i]
	if p.Name == "http" {
		p.Port = 8080
	}
}

    Copying the slice into a local variable (ports := svc.Spec.Ports) is fine: the copy is a small header pointing to the same backing array, so element changes are visible through svc.Spec.Ports. Only append on the local copy would diverge.

    After this runs, what is svc.Spec.Ports[0].Port?

    
ports := svc.Spec.Ports   // ports[0].Port was 80
ports[0].Port = 8080

    Assigning a slice copies its header (pointer, length, capacity), not its elements. Unlike a range value variable, ports[0] refers to the shared element.

    Reporting every problem with errors.Join

    Validation should report all problems at once, not stop at the first. Collect errors in a slice and join them (Go 1.20+):

    
var (
	ErrNoPorts  = errors.New("at least one port is required")
	ErrBadPort  = errors.New("port must be 1-65535")
)

func validateService(s *Service) error {
	var errs []error
	if len(s.Spec.Ports) == 0 {
		errs = append(errs, ErrNoPorts)
	}
	for _, p := range s.Spec.Ports {
		if p.Port < 1 || p.Port > 65535 {
			errs = append(errs, fmt.Errorf("port %q: %w", p.Name, ErrBadPort))
		}
	}
	return errors.Join(errs...) // nil if errs is empty
}
    • errs... spreads a slice into a variadic call.
    • errors.Join returns nil when there are no non-nil errors, so you don't need an if.
    • The joined error prints one problem per line, and errors.Is(err, ErrBadPort) finds any of them, even wrapped ones.
    From Kubernetes

    The API server's validation works the same way, using a field.ErrorList. That's why a bad kubectl apply lists every invalid field in one response.

    err := errors.Join(ErrNoPorts, fmt.Errorf("port %q: %w", "http", ErrBadPort)). Which is true?

    errors.Is searches every branch of a joined error and every layer of %w wrapping.

    Reading files and testdata/

    
data, err := os.ReadFile("testdata/service.yaml") // ([]byte, error)
if err != nil {
	return err
}
    • go test runs with the working directory set to the package's folder, so test files can use relative paths like testdata/....
    • The Go tool ignores folders named testdata when building, so fixtures there never end up in your program.
    • In test helpers, call t.Helper() first. Failures are then reported at the line that called the helper, which is the line you care about.
