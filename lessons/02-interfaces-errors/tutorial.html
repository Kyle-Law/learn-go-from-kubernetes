    Interfaces and errors: a toy API server

    kubectl get works on Pods, ConfigMaps and CRDs it has never heard of, and every client-go call can fail with a NotFound or Conflict. This tutorial covers the two Go features behind that: interfaces and error values.

    • About 35 minutes
    • 10 self-checks
    • Then: object.go, errors.go, store.go

    Why interfaces?

    Suppose you want one function that can print the name of any Kubernetes object. In lesson 1 every function took a concrete type like Pod. To accept "anything with a name" you describe the behaviour you need, not the type:

    
type Named interface {
	GetName() string
}

func printName(obj Named) {
	fmt.Println(obj.GetName())
}

    An interface is a list of method signatures. Any value whose type has those methods can be passed to printName.

    From Kubernetes

    controller-runtime's client.Object is an interface combining metav1.Object (GetName, GetNamespace, GetLabels, …) and runtime.Object. That's why client.Get(ctx, key, obj) works for Pods, Deployments and your own CRDs alike.

    Interfaces are satisfied implicitly

    There's no implements keyword. If a type has the methods, it satisfies the interface, even if its author never heard of the interface.

    
type Scalable interface {
	Scale(replicas int32)
	CurrentReplicas() int32
}

type Deployment struct{ replicas int32 }
func (d *Deployment) Scale(n int32)          { d.replicas = n }
func (d *Deployment) CurrentReplicas() int32 { return d.replicas }

type StatefulSet struct{ replicas int32 }
func (s *StatefulSet) Scale(n int32)          { s.replicas = n }
func (s *StatefulSet) CurrentReplicas() int32 { return s.replicas }

func scaleToZero(objs []Scalable) {
	for _, o := range objs {
		o.Scale(0)
	}
}

scaleToZero([]Scalable{&Deployment{replicas: 3}, &StatefulSet{replicas: 2}})

    Two consequences:

    • Interfaces belong to the code that uses them. You can define a small interface next to the function that needs it, and existing types satisfy it with no changes.
    • Keep interfaces small. The most-used ones have a single method: error (Error() string), fmt.Stringer (String() string), io.Reader (Read).

    Compile-time checks

    Because nothing declares "this type implements that interface", Go code often adds a line that makes the compiler verify it:

    
var _ Scalable = &Deployment{} // fails to build if *Deployment stops satisfying Scalable

    The _ means "I don't need this variable". You'll see this line all over Kubernetes, and at the top of object_test.go.

    You add a type DaemonSet struct{...} with Scale(int32) but forget CurrentReplicas(). What happens when you pass &DaemonSet{} to scaleToZero?

    A type must have every method in the interface, and the compiler checks this where the value is converted to the interface. It doesn't matter which methods the function happens to call.

    Pointer receivers and interfaces

    In the example above, the methods have pointer receivers, (d *Deployment). That means *Deployment satisfies Scalable, but Deployment does not:

    
var a Scalable = &Deployment{} // OK
var b Scalable = Deployment{}  // compile error: method Scale has pointer receiver

    When you call d.Scale(3) on a variable, Go takes &d for you. When it checks whether a type satisfies an interface, it doesn't: the set of methods on Deployment (its method set) only includes value-receiver methods.

    Kubernetes types put their methods on pointers, so you always pass &corev1.Pod{} to the client, never corev1.Pod{}.

    Embedding: shared metadata

    Every Kubernetes resource has metadata with a name, namespace and labels. Go shares that structure by embedding a struct: listing its type without a field name.

    
type ObjectMeta struct {
	Name      string
	Namespace string
}

func (m *ObjectMeta) FullName() string { return m.Namespace + "/" + m.Name }

type Secret struct {
	ObjectMeta              // embedded: no field name
	Data map[string][]byte
}

s := &Secret{ObjectMeta: ObjectMeta{Name: "db-creds", Namespace: "prod"}}
fmt.Println(s.Name)        // promoted field: really s.ObjectMeta.Name
fmt.Println(s.FullName())  // promoted method: "prod/db-creds"

    The embedded struct's fields and methods are promoted to the outer type. Promoted methods count toward interfaces: if an interface needs FullName(), *Secret now satisfies it.

    In a composite literal, the embedded field's name is its type name: ObjectMeta: ObjectMeta{...}.

    Trap

    Embedding is composition, not inheritance. A *Secret is not an *ObjectMeta: you can't pass one where the other is expected. If you need the inner value, ask for it: &s.ObjectMeta. For "works with many types", use an interface.

    If the outer type defines a field or method with the same name, the outer one wins (it "shadows" the embedded one). The embedded one is still reachable as s.ObjectMeta.Name.

    From Kubernetes

    Every real type looks like type Pod struct { metav1.TypeMeta; metav1.ObjectMeta; Spec PodSpec; Status PodStatus }. ObjectMeta has the GetName(), GetLabels()… methods, and embedding is how every resource gets them and satisfies metav1.Object.

    Given the Secret type above, which line compiles?

    The embedded value is a field named ObjectMeta; take its address to get an *ObjectMeta. There's no subtype relationship, and .(...) only works on interface values.

    Type assertions and type switches

    An interface variable hides the concrete type. You can only call the interface's methods on it:

    
var obj Named = &Secret{...}
obj.GetName()      // OK: GetName is in the interface
obj.Data           // compile error: Named has no field Data

    Checking something like obj.GetKind() == "Secret" doesn't help: the compiler only knows the static type, Named. To get the concrete type back, use a type assertion:

    
s, ok := obj.(*Secret)   // ok is false (and s is nil) if obj isn't a *Secret
if ok {
	fmt.Println(len(s.Data))
}

s := obj.(*Secret)       // single-value form: PANICS if obj isn't a *Secret

    Type switches

    To handle several possible types, use a type switch. In each case, the variable has that case's concrete type:

    
func size(obj Named) int {
	switch o := obj.(type) {
	case *Secret:
		return len(o.Data)            // o is *Secret here
	case *ServiceAccount:
		return len(o.Secrets)         // o is *ServiceAccount here
	default:
		return 0                      // o is still Named here
	}
}

    The empty interface, any (also written interface{}), has no methods, so every value satisfies it. You'll use assertions on any values often.

    From Kubernetes

    Informer event handlers receive obj interface{}. On delete, it can be either your type or a cache.DeletedFinalStateUnknown tombstone, so real controllers use a comma-ok assertion or a type switch, never the panicking form.

    What is the type of o inside this case?

    
switch o := obj.(type) {
case *Secret, *ServiceAccount:
	// ...
}

    o only gets a concrete type in a case that lists exactly one type. With two, Go can't pick, so o keeps the switched-on interface type. Use separate cases if you need the fields.

    obj holds a *ServiceAccount. What does s := obj.(*Secret) do?

    The single-value form panics on a mismatch. Use s, ok := obj.(*Secret) unless you're certain of the type.

    Errors are values

    Go has no exceptions. A function that can fail returns an error as its last result, and the caller checks it right away:

    
data, err := os.ReadFile("deployment.yaml")
if err != nil {
	return fmt.Errorf("reading manifest: %w", err)
}
// use data
    • if err != nil { return ... } is the most common line in Go. It's deliberate: every failure point is visible.
    • Convention: when err != nil, the other results are zero values and the caller shouldn't use them. When you return an error, return nil/0/"" for the rest.
    • When there's no error, return a literal nil.

    error is just an interface

    
type error interface {
	Error() string
}

    Anything with an Error() string method is an error. That means you can make your own error types that carry extra data:

    
type QuotaError struct {
	Resource string
	Limit    int
}

func (e *QuotaError) Error() string {
	return fmt.Sprintf("exceeded quota for %s (limit %d)", e.Resource, e.Limit)
}

func createPod(n int) error {
	if n > 10 {
		return &QuotaError{Resource: "pods", Limit: 10}
	}
	return nil
}

    A lookup function's signature is func findNode(name string) (*Node, error). The node doesn't exist. What should it return?

    On failure, return zero values for everything except the error. Returning an empty &Node{} invites callers to use a fake node; nil, nil hides the failure entirely.

    Wrapping errors, errors.Is and errors.As

    As an error travels up the call stack, each layer adds context with fmt.Errorf:

    
err := createPod(12)
err = fmt.Errorf("scaling web: %w", err)
err = fmt.Errorf("reconciling default/web: %w", err)
fmt.Println(err)
// reconciling default/web: scaling web: exceeded quota for pods (limit 10)

    The %w verb wraps: the new error keeps a reference to the original, forming a chain. Callers can then search that chain.

    errors.Is: "is this specific error somewhere in the chain?"

    
if errors.Is(err, ErrNoNodes) {
	// retry later
}

    errors.As: "is there an error of this type in the chain? Give it to me."

    
var qe *QuotaError
if errors.As(err, &qe) {
	fmt.Println("limit was", qe.Limit) // qe now points at the QuotaError in the chain
}

    You pass a pointer to your variable (&qe) so errors.As has somewhere to store the match.

    Trap

    %v only copies the error's text into a new error. The chain is broken, so errors.Is and errors.As can no longer find the original. Use %w when you return an error with added context.

    Trap

    Never decide what to do by comparing error text (err.Error() == "..." or strings.Contains). Messages are for humans and change. Check values with errors.Is and types with errors.As.

    From Kubernetes

    client-go returns *apierrors.StatusError, which carries a reason (NotFound, AlreadyExists, Conflict, …) and an HTTP code. Helpers like apierrors.IsNotFound(err) use errors.As to find it and check the reason. Controllers branch on these constantly: not found usually means "it was deleted, nothing to do"; conflict means "re-read and retry". Check the reason, not just the code: AlreadyExists and Conflict are both HTTP 409.

    err wraps a *QuotaError. After this line, does errors.As(wrapped, &qe) find it?

    
wrapped := fmt.Errorf("reconcile failed: %v", err)

    Only %w wraps. With %v, the original error and its type are gone.

    What's wrong here?

    
var qe *QuotaError
if errors.As(err, qe) {
	fmt.Println(qe.Limit)
}

    qe is a nil *QuotaError, which gives errors.As nowhere to write. It compiles because the parameter is any, but go vet flags it.

    The nil interface trap

    An interface value holds two things: a type and a value. It equals nil only when both are nil.

    
func check() error {
	var qe *QuotaError   // nil pointer
	if quotaExceeded() {
		qe = &QuotaError{Resource: "pods", Limit: 10}
	}
	return qe            // BUG when quota is fine
}

err := check()
fmt.Println(err == nil) // false! err holds (type=*QuotaError, value=nil)

    The caller sees a non-nil error, and calling err.Error() may then panic on the nil pointer. The fix: return a literal nil on the success path.

    
func check() error {
	if quotaExceeded() {
		return &QuotaError{Resource: "pods", Limit: 10}
	}
	return nil
}

    It's fine for constructors to return a concrete pointer type like *QuotaError; just don't store a possibly-nil typed pointer in an error and return it.

    An interface variable holds (type=*Pod, value=nil). Is it == nil?

    An interface is nil only when it has no type and no value. A typed nil pointer inside makes it non-nil.

    Map-backed stores and sorting

    The exercise builds an in-memory store, like a tiny etcd. A few patterns make that straightforward.

    Composite keys

    A map key must uniquely identify an object. In Kubernetes, a name alone isn't unique: a Pod and a ConfigMap can share a name, and so can two Pods in different namespaces. Build a key from all the parts:

    
type NodeRegistry struct {
	nodes map[string]*Node // keyed by "zone/name"
}

func nodeKey(zone, name string) string { return zone + "/" + name }

    Storing interfaces

    A map[string]Named can hold any type that satisfies Named. You put in a *Secret, you get back a Named, and the caller uses a type assertion to get the *Secret back.

    Sorting

    Map iteration order is random, so a list built by ranging over a map must be sorted before you return it. Go has two ways:

    
// sort.Slice: "less" function comparing elements by index
sort.Slice(nodes, func(i, j int) bool {
	return nodes[i].Name < nodes[j].Name
})

// slices.SortFunc (Go 1.21+): compare function returning -1, 0 or +1
slices.SortFunc(nodes, func(a, b *Node) int {
	return strings.Compare(a.Name, b.Name)
})

// Sort by zone, then name (Go 1.22+): cmp.Or returns the first non-zero result
slices.SortFunc(nodes, func(a, b *Node) int {
	return cmp.Or(
		strings.Compare(a.Zone, b.Zone),
		strings.Compare(a.Name, b.Name),
	)
})
    Tip

    slices and cmp are in the standard library: import "slices". If your editor auto-imports golang.org/x/exp/slices, that's an older experimental copy; switch to the standard one.

    The store hands out pointers

    When the map holds pointers, a Get returns the same pointer that's stored. If the caller modifies it, they've modified the stored object, with no Update call.

    From Kubernetes

    Informer caches work exactly like this. Objects you get from a lister are shared with the cache, so the rule is: never modify them. Call obj.DeepCopy(), change the copy, then send it with Update.

    You want Remove(key) to return an error when the key doesn't exist. Is delete(m, key) enough?

    delete returns nothing and never fails. Look the key up with _, ok := m[key] first if missing keys should be an error.

    The registry stores *Node. A caller does n, _ := reg.Get("a", "worker-1") and then n.Unschedulable = true. What does the next Get return?

    Both the map and the caller hold the same pointer. That's convenient here and dangerous in an informer cache, which is why Kubernetes code calls DeepCopy() before changing anything.
